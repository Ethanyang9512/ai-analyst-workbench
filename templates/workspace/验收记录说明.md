# 验收记录说明（工作区里的 `_acceptance/`）

> 每个工作区最上层有一个 `_acceptance/records.jsonl`：正式交付物发出前验收过一次，就记一行。
> 谁写：`runtime/tools/accept_record.py write`（分析助手在验收员的必须改都修完后运行）。
> 谁读：`runtime/hooks/gate.py`（验收门，发送前查这个文件的内容指纹有没有记录）、`accept_record.py status`（判断该不该全稿通读）。
> **文件内容变了要重新验收、重新记录**：门只认指纹，改一个字节记录就失效。
> 这个目录是真实的交付记录，不要提交到公开仓库（仓库的 `.gitignore` 已排除 `_acceptance/`）。

## 每一行的字段

| 字段 | 含义 |
|---|---|
| `ts` | 记录时间（本地时间，`YYYY-MM-DD HH:MM:SS`） |
| `epoch` | 同一时间的秒数，程序比较用 |
| `files` | 这次验收的文件列表，每项 `{"path": 相对工作区的路径, "sha256": 内容指纹}` |
| `doc` | 只验飞书文档、不带文件时写文档标题或链接；否则为空 |
| `tier` | 档位：`small`（小改）/ `page`（大改）/ `full`（全稿通读）；没写记 `unspecified`，不算全稿 |
| `pages` | 这次涉及的页，自由文本（“5,6,24”“5-7”“第3页、封面”都行） |
| `reader` | 读者验收员（`cold-reader`）的一句话结论；没请就写“不适用：原因” |
| `visual` | 图表数字验收员（`chart-number-checker`）的一句话结论；没请就写“不适用：原因” |
| `note` | 其他说明，例如没有 scope 可用时为什么这样定档 |

## 常用命令

```bash
python3 "$AAW_RUNTIME/tools/accept_record.py" write --file 报告_v1.pdf --tier full --pages "全稿" \
        --reader "冷读通过，1 处术语首次出现补了解释" --visual "8 张图看过，核了 12 个数，无必须改"
python3 "$AAW_RUNTIME/tools/accept_record.py" check --file 报告_v1.pdf     # 有记录返回 0
python3 "$AAW_RUNTIME/tools/accept_record.py" status                       # 起点以来几条记录、该不该全稿通读
python3 "$AAW_RUNTIME/tools/accept_record.py" list                         # 最近 10 条
```

`status` 建议全稿通读的条件（满足任一条）：最近一次全稿验收之后满 5 条记录、涉及满 8 页、或超过 3 天。
