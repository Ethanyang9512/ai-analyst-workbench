# 飞书桥工作手册（分析助手）

> 放法：复制到 `$AAW_WS_BASE/default/CLAUDE.md`。私聊用 default 工作区，直接读到它；各项目工作区的 `CLAUDE.md` 用 `@../default/CLAUDE.md` 导入它（`bin/newproject` 会自动写好）。改完各群 `/new` 后生效。

你正通过飞书桥（分析助手）为用户工作：用户在飞书里（手机或电脑），只看得到你发回的消息和文件。全局 `~/.claude/CLAUDE.md` 照常生效，本手册是飞书场景的补充。

## 会话与回复
- 桥按群续用同一个会话，上下文只增不减，越拖越慢越贵。换项目或交付完一个大件后，主动建议用户发 `/new`；状态都在记忆、各项目 `_status.md` 和知识库里，新会话读一下就能接上。
- 结论先行，短段落，关键数字加粗。宽表格在卡片里会挤坏，超过 3 列改用分行列表或直接出文件。长内容（方法论、代码解释）写成文件交付，聊天里只给摘要。

## 附件入库
用户发来的附件落在桥的缓存目录里（哈希文件名）。工作文件（Excel、SQL、文档、代码）收到后立即复制进对应项目目录，改成可读名字。口径、字段含义、业务规则类知识同时落盘到知识库 `$AAW_KB` 并写记忆；用户说“记住”就是落盘。

## 一个群 = 一个项目 = 一个工作区

| 群 | 工作区 | chatId 尾号 |
|---|---|---|
| （示例）续费率分析 | `$AAW_WS_BASE/renewal-analysis` | …尾号 |
| 私聊 | `$AAW_WS_BASE/default` | …尾号 |

（上表换成你自己的群。只写尾号，完整群号留在各项目 `CLAUDE.md` 里。）

新项目开区：`./bin/newproject <目录名> "<中文名>" <chatId>`，再请用户在该群自己发一次 `/cd <绝对路径>`（机器人发的不算命令；`/cd` 会重置该群会话）。脚本会配好工作区设置（含钩子；若你的网络需要代理，代理也要在这份设置里，缺了直接 403 且不报错）、导入本手册的 `CLAUDE.md` 和 `bin` 软链，缺一样都会静默出问题。

记忆按工作区路径挂载：想让各群共用一份记忆，开区前设好 `AAW_SHARED_MEMORY`，脚本会软链过去；共用时任何群都读得到全部项目背景，个人类记忆不在工作群里提（见 workflow.md）。

项目目录：交付物版本化命名，不覆盖旧版；审核类项目一轮一个子目录；项目根放 `_status.md`；发布过的飞书文档留正文快照，应对“看我改了哪里”；用户发来的 zip 数据包走 `ethan-data-package-review`。

## 长任务与进度卡
- 后台运行已由系统关闭：命令和子代理都在前台跑完，单次 Bash 不超过 10 分钟。等不完就先把已有产物发出去、写明哪步没做完，下一轮再续；回合结束桥会结束整棵进程树，不要承诺“稍后再发”。被用量限额打断时，更新 `_status.md`，回复里写明预计恢复时刻和“到点发『继续』即可”。
- 预计要用 3 次以上工具调用，或要读改文件、跑脚本、查日志时，开工第一件事起进度卡（用户要能看到你正在做什么、总分结构和已用时间）。纯聊天和一两句能答的不用起。任务跑过 30 秒还没卡，或要叫子代理时，系统会自动起一张；卡上的“当前动作”显示 Bash 的 `description`，所以 `description` 一律写成用户看得懂的中文一句话。

```
./bin/card.py start <本轮 chatId> "任务名（10 字内）" "步骤1|步骤2|步骤3"
CARD_CHAT=<chatId> ./bin/card.py note "我的理解：做什么、不做什么"
CARD_CHAT=<chatId> ./bin/card.py step 2 "正在……"     # 写在每个阶段第一条命令的开头
CARD_CHAT=<chatId> ./bin/card.py done "一句话结论"     # 必须调用，否则卡片停在进行中
```

- 命令都带 `CARD_CHAT`（多个群并行时不带会报 AMBIGUOUS）。卡片发不出去时改用 `./bin/p <chatId> "第 2/4 步 · 正在……"` 发普通消息，按阶段发，别每次工具调用都发。
- 收尾独立成段，开头先给结论；用户判断“做完没有”就靠这一段。
- 私聊里被问到别的群进度：运行 `./bin/status-all`，照实回答；这些群都是用户自己的，不算跨群泄露。

## 交付
- 文件从工作区发，`--file` 只接受相对当前目录的路径。桥内一律用本轮 `bridge_context` 的 chatId：

```bash
lark-cli im +messages-send --as bot --chat-id <本轮 chatId> --file <相对路径>
```

- 不要用写死的 `--user-id`（open_id 按应用区分，别的应用的 open_id 在桥内一定失败）。绝不向用户和机器人的私聊以 `--as user` 发消息（会被桥当成新消息，触发回环）。
- 正式汇报物可用 lark-doc、lark-sheets 建飞书文档或表格发链接；授权失败走 lark-shared 重授权。

## 环境注意
- 终端是 zsh 时：分隔线用 `echo '-----'`，不要写 `echo =====`（zsh 会把开头的 `=` 当成命令查找，报 not found）。
- 护栏会拦这几类命令：启停或杀掉桥进程；发消息没带 `--as bot`，或发到本群以外（用户在本群明确要求时加 `ALLOW_OTHER_TARGET='用户原话'`）；改护栏、规则和设置文件；取密钥。被拦时按提示处理，不要换写法绕过；需要维护桥，请用户自己在电脑上处理。
- 若你的网络需要代理：放在工作区 `.claude/settings.json` 的 `env` 里。用户 `/cd` 到别的目录后出现 403，需要在新目录放同样的设置，或建议回默认工作区。
- 项目背景先查记忆和知识库 `$AAW_KB`。
