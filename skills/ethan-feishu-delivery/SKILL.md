# 把成果发到飞书

先做完本轮授权的产物和检查，再发。发消息、读写文档的具体命令以你装的 lark-cli 为准，先看 `lark-cli <命令> --help`；文档、表格的创建和更新交给对应的飞书文档技能，不要把它们当成普通消息发。

## 先确定“以谁的身份、发给谁”

- **在飞书桥里**（环境变量 `LARK_CHANNEL=1`，或本轮消息带 `bridge_context`）：用桥绑定的机器人身份，`--as bot --chat-id <本轮 bridge_context 里的 chatId>`。收件目标每次都从本轮上下文取，不从历史目录、旧的私聊编号或别的应用里猜。
- **在终端或桌面对话里**：只有用户要求发飞书时才发。目标从用户的指令、或已经核实过的群和联系人里定；只有缺的信息会影响发给谁时才问。“做成文档给我”不等于要发到飞书。
- **不用用户身份往机器人监听的会话里发成果。** 桥会把它当成用户的新消息，助手再回复自己，循环下去（回环）。
- 授权失败时，诊断当前身份；不换应用、不扩大权限、不复制别处的凭据来绕过。

## 命令

```bash
lark-cli im +messages-send --as bot --chat-id <本轮chatId> --markdown '成果说明'
lark-cli im +messages-send --as bot --chat-id <本轮chatId> --file 相对路径/成果.xlsx
```

`--file` 通常只接受当前目录下的相对路径：先进入文件所在目录，或把本轮的文件复制进工作区。本机绝对路径、Markdown 里的本地链接，在飞书里（手机或电脑上）都打不开，不算交付。

## 发之前：阶段检查

桥提供了本轮的阶段检查命令时，在上传文件、覆盖线上文档和发送之前，单独跑一次这条命令，读它返回的 `action`：只有 `continue` 才往下做；其他结果（让位、暂停、过期、不可用）照本轮说明停下，把已有产物、上传结果和回执记进项目状态，下次接着做之前先核对，避免重复上传或重复发送。这条命令只对当前回合有效，不复用以前的。

## 发什么、怎么确认发到了

- 说明里写清：用途、哪一份是正式入口、和上一版有什么不同、下一步。给协作方的转交，一个包里给齐所需信息。
- Excel、PPT、ZIP 发原件；在线文档核对真实链接和访问范围；没发布的本机网页不能说成线上链接。
- **正式交付物发出前要有验收记录**（用分析助手运行时的验收门时）：PPT、Excel、Word、PDF 和新建的飞书文档，发送命令执行前，验收门会查工作区的 `_acceptance/records.jsonl`。所以生成文件、写验收记录、发送要分成三条命令。中间文件或用户说不用验收时，在发送命令前加 `ACCEPT_SKIP='理由'`。回复里写一行验收结果。
- 区分“已生成 / 已核验 / 已发送 / 发送失败”。按 lark-cli 返回的 JSON 判断成败，保留消息或文件的回执。
- 超时或结果不明时，先查回执和目标会话，再决定要不要重发。
- “只讨论”“等数据”“先别发”优先于本技能。飞书里发起、已经要求做完就交付的任务，做好后直接交付，不再问一次要不要发。
