# 写进飞书文档时的实操

> `report-writing` 的参考文件。成品要写进飞书文档时读；不用飞书就跳过。命令以你装的 lark-cli 版本为准，先看 `--help`。

## 流程图：用画板引本地文件

```
<whiteboard type="mermaid" path="@相对路径/flow.mmd"></whiteboard>
```

用 `path` 引用本地 `.mmd` 文件，比把图写进 XML 少一层转义。画板支持 mermaid 的 flowchart、子图泳道、饼图和 xychart。`xychart-beta` 没有图例，多条线分不清：要么只画两条并在标题里写清谁在上，要么改用 matplotlib 出图。改图时替换整个画板块。

## 插图片的三个坑

```bash
lark-cli docs +media-insert --doc <document_id> --as user \
  --file <相对当前目录的路径>.png --align center --width 920
```

1. `--doc` 要的是 document_id，不是 `/wiki/` 链接。
2. 图片只能插在文末，之后要移到锚点后面（`block_move_after`）。
3. 命令输出里进度信息在 JSON 前面，直接整段解析会失败；用正则取 `"block_id"`。解析失败**不要重试插入**，先回读文档确认，否则会插出重复的图。

## 覆盖重推正文会冲掉图片

用覆盖方式重推整篇正文后，之前插入的图片会全部消失（画板按 `path` 能重建，图片不能）。所以：

- 改了正文：覆盖重推 → 重新插全部图片 → 逐张移回原位；
- 只改图：替换那一个块，不要覆盖整篇。

批量插图或换图后，按章节列一遍图片分布（回读全文，按标题和图片出现的顺序打印），确认没有图掉在文末或错章。移位失败常常是静默的。

## 查样式要取完整信息

回读默认只取简版，不带单元格底色这类样式，会让人误以为样式没生效。查样式时加取完整信息的参数（如 `--detail full`）。

## 发布后留快照

每次发布或大改后，把正文回读存一份到项目的 `_doc_assets/`。用户常见的协作方式是直接改线上文档，再说“看我改了哪里，按这个思路改全篇”：有快照就能比出精确的改动点，再推广到全文；没有快照只能猜。比出改法后，照 `SKILL.md`「成对稿与考题」把这一对存下来。
