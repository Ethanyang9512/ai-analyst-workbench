# 禁用词台账

> 记录用户纠正过、交付前必须拦下的写法。`scripts/style_lint.py` 只读下面「一、硬禁」这张表，追加一行即生效。
> **这是示例台账，换成你自己的。**表里 8 条是常见的示例，不代表任何人的偏好；保留表头和三列结构即可。
> 怎么加、什么时候升进硬禁、作废的挪去哪里，见 `SKILL.md`「修正即沉淀」。作废条目挪到同目录 `style-lexicon-archive.md`。
> 适用范围：给业务看的交付文档。和用户聊天时不受限。

## 一、硬禁

「禁用」列的写法：

- `A / B` 或 `A／B`：几个词分别匹配（所以本身带斜杠的词写不进这一列）；
- 省略号 `…` `……` `...`：中间可以夹 0–6 个字（不跨标点和表格竖线），例如「值得…注意的是」也拦「值得特别注意的是」；
- `X`：代表一个数（阿拉伯或中文数字），例如「如图X所示」拦「如图3所示」。英文单词里的 X 照字面。

「来源」列只写三种：**用户纠正**（用户原话或亲笔改写）、**协议**（规则本身要求）、**两份文档复现**（从改动推断、过了门槛）。日期和出处记在归档文件的出处索引里。

| 禁用 | 改成 | 来源 |
|---|---|---|
| 值得…注意的是 | 删，直接陈述 | 协议 |
| 众所周知 | 删 | 协议 |
| 赋能 | 写出具体动作（“让客服能直接退款”） | 协议 |
| 抓手 | 写出具体做法 | 协议 |
| 断崖式 | 下降，并写出幅度 | 用户纠正 |
| 我们认为 / 我们判断 | 数据显示 | 两份文档复现 |
| 如图X所示 | 删，直接写图里的结论 | 协议 |
| 仅供参考 | 删（不写自我削弱的话） | 用户纠正 |

## 二、警告（程序报出，人工判断）

写在 `style_lint.py` 里，不读这张表：

1. % 和 pt 疑似混用：“下降”“差距”这类词后面跟着 `N%`，提示核对单位。
2. LaTeX 写法 `$…$`：贴进飞书会乱码。
3. 第二人称“你”：业务文档写角色名。

## 三、程序拦不住的（写作时自查）

程序只查词，查不了句式和判断。下面这些靠写的时候对照：

1. 不预告紧跟其后的列表条数：“下降的两个原因”写成“下降的原因”。客观计数不受限。
2. 不写交代论证进度的句子（“至此第一步完成”“与上一节互相印证”）。
3. 不写预防质疑的澄清句和方法辩护；读者真会问的放进“需要关注”。
4. 第一章已有结论，文末不再重复一遍。
5. 不直接支撑行动的推演放详细版。
6. 表格的引导句写一句“××口径：”就够。
7. 抽象规则后面紧跟一个具体例子。
8. 一段一件事；连续说理的长段改成列表。

## 四、只适用于一个项目的纠正

按下面格式追加在本节之后。`style_lint.py` 不读这些小节；同类纠正第二次出现时，写进那个项目的 `_CONVENTIONS.md` 的 json 块，由 `deckcheck.py` 去查。

```
## <日期> · <项目名>（本项目适用）

| 禁 | 改成 | 依据 |
|---|---|---|
| <原词> | <改成> | 用户原话："……" |
```
