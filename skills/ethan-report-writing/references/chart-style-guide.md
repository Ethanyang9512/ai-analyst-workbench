# 出图与表格规范

> `ethan-report-writing` 的参考文件。出图、做表、做 Excel 图表包之前读。选什么图型看 `ethan-pyramid-storyline/references/chart-chooser.md`，这里只管画法和自检。出图脚本从 `scripts/chart_template.py` 起步，它已经按本规范设好了字体、配色和柱宽。

## 一、配色：黑灰红，绿红只表达好坏

先问一句：这个颜色是在**区分系列**，还是在**表达好坏**？区分系列只用黑灰；表达好坏才用绿红，而且两者成对出现，同一篇文档里含义一致。

| 角色 | 色值 | 用在哪 |
|---|---|---|
| focus 主角 | `#1A1A1A` | 主系列，一张图最多一个 |
| compare 对照 | `#B9B9BC` | 次系列、对标 |
| context 背景 | `#DDE0E4` | 背景参照、极淡的分隔 |
| accent 强调 | `#C0392B` | 目标线、累计线、分水岭、差值标注 |
| up 正向 | `#2E9E5B` | 拉动、改善（语义色） |
| down 负向 | `#D64545` | 拖累、变差（语义色） |
| 热力五档 | `#1B7F4F` `#63B37E` `#F2C94C` `#E8873A` `#D64545` | 高到低，必须配图例 |

这张表是文档和汇报片的唯一配色来源。改了色值，要同步改 `scripts/chart_template.py` 和 `ethan-slide-deck/scripts/check_deck.py` 的合法色表。品牌色只给页面色块和封面用，不给图上色。

## 二、出图硬约束

| 项 | 规定 |
|---|---|
| 背景和外框 | 纯白，不套卡片、边框、标题条。套了会像从别的系统截图贴进来，和正文割裂 |
| 画布比例 | 文档里约 2.2–2.4 : 1（如 10.6 × 4.8 英寸）；接近正方会显得挤 |
| 柱宽 | 单系列 0.30–0.36，簇状 0.22–0.26；matplotlib 默认的 0.8 太胖 |
| 纵轴 | 不要轴标签、刻度和左边框；纵轴含义写进副标题，数字靠数据标签 |
| 网格线 | 一律不要 |
| 标签 | 柱图全标；折线 8 个点以上只标起点、拐点、终点和事件点 |
| 很小的类别 | 小到看不见的柱并进相邻一档（“2 件及以上”），不单列 |
| 折线 | 默认画平滑线（项目约定页可改）：点少用单调三次插值（PCHIP），不用普通样条，否则会过冲到不可能的值；点多画移动平均作主线，原始值用淡色细线垫底 |
| 注记 | “仅展示前 20 项”这类放右下角灰色小字，别压住旋转后的横轴标签 |
| 双轴图 | 柱值标签贴柱底、柱内白字，避开累计线 |
| 排名变化 | 用斜率图（每个时点一栏，名次 1 在最上），不用 bump chart 和哑铃图：读者要同时记住的映射规则越少越好 |
| 标题 | 只写读者第一眼能在图上验证的结论；分组依据放副标题 |
| 字体 | 中文回落链 PingFang SC → Noto Sans CJK SC → Arial Unicode MS；西文想用品牌字体时设 `AAW_LATIN_FONT` |

删掉某个时段或分组之前，先问它对读者有没有参照价值：中间那个时段常常正是最好的对照。

换风格、换字体或换配色时，先出一张样图给用户确认，再批量重出。

## 三、出图后自检

每张图先跑 `scripts/figcheck.py`（查文字重叠、折线穿字、出界、被裁），再自己打开 PNG 看一遍，把自己当成第一次看这张图的人：

1. 文字有没有重叠、被线穿过、被图例压住？标签有没有出界或被裁？
2. 中文有没有变成方框？（换字体后必查）
3. 还有没有卡片、边框、标题条？柱子胖不胖，画布方不方？
4. 有没有读者看不懂的符号（∩、Σ）？写成“与”“合计”。
5. 数一遍标签个数：几个系列就该有几个标签。少一个多半是被别的点盖住了。
6. 副标签（百分比、增量）是不是又小又浅、紧贴主数字？能并进主数字就并成一行，并不进就加深颜色、拉开距离；增量标注用深灰底白字，不用绿红（会暗示好坏）。
7. 折线是否平滑、有没有过冲出合法范围？
8. 标题说的事，图上第一眼能不能看出来？

改口径或术语时，图里的文字要一起改：正文统一了、图注没改，是最容易漏的一处。

## 四、图和表的分工

图负责让人看出好坏，表负责给精确的数，两者不要同时上色抢注意力。配了图的章节，表格保持素净；没配图的表才用单元格底色。多行多指标的核心表，可以用 matplotlib 渲染成图片（灰底槽加数据条、零点竖线分正负、隔行浅灰），对象 × 时间的矩阵用热力图并配图例。

## 五、同一份分析既出文档又出汇报片

图只做一套，开两个输出档，不要各写各的：

| 项 | 文档档 | 汇报片档 |
|---|---|---|
| 图内主副标题 | 有 | 没有：页标题和要点句已经说了 |
| 画布比例 | 2.2–2.4 : 1 | 跟着页面上的图区走（左图右文约 1.8 : 1） |
| 单位和口径注记 | 右下角灰色小字 | 同左，必须保留 |
| 尺寸 | 按英寸 | 按图区的厘米折算，插进去 1:1 不缩放 |

汇报片里的数据图默认要可编辑（见 `ethan-slide-deck`）。只有用户接受静态图、或这种图型做不成可编辑对象时，才插 PNG；需要原生图表做不出的效果（差值标注、平滑线、斜率图）时，先说明取舍。

## 六、Excel 图表包

分析文档默认配一个 Excel 图表包：文档里每张图对应一个子表，放数据区和一张 Excel 原生图，业务可以自己改数重画。公式留在单元格里、简单可读；明细页原样保留；参数集中放在一处并标色；另有 README 页和方法说明页。细则见 `ethan-reproducible-analysis`。

## 七、写给业务的两条内容纪律

**不写口径的修正过程。** 业务只需要知道现在的口径是什么、怎么算。例（虚构）：不写“加总 9.4% 含重复，去重后 6.6%，再剔除已退款的得 5.8%”，只写“受影响的订阅占 5.8%”，再列出两条判定规则（一个订阅只算一次、已退款的不算）。

**交付文档里不用代码块。** 公式和测算过程这样改写：

| 原来的样子 | 改成 |
|---|---|
| 带根号、分式的公式 | 公式块放在章节开头，正文跟一行说明每个字母 |
| 逐行等式的测算 | 两列表格（项目 / 数值） |
| 判定规则的举例 | 对照表（情形 / 算不算 / 原因） |
| 一步换算 | 写进句子：“2.0 万个到期订阅里 2,800 个是年付首次续费，占 14.0%”（虚构） |
| 多步推导 | 正文顺着写，用“假设……对应……据此”衔接 |
| 流程和环节关系 | mermaid 流程图 |
