# 可打印的自检清单

> `ethan-pyramid-storyline` 的参考文件。交付前对着打勾；按本轮目的取用。

## 骨架

- [ ] 新分析、新角度在取数前写过故事线清单；交稿时，写成结论的章首句都是“已证实”；没验证完的只能以一行“原因待××确认”出现（状态留待验证），或移出正文。
- [ ] 第一章第一句就是结论，带最该记住的那个数。
- [ ] 第一章不超过一屏：2–4 条结论，每条一句加粗判断加至多一句支撑；没有口径段和方法段。
- [ ] 每章首段是这一章的结论；判定口径和方法在章末或口径说明里。
- [ ] 章首句加图标题连着读，是一份完整的汇报。
- [ ] 第一章的建议一段说完：每条一句，谁、做什么、什么时候；诊断专题里每条建议的四件事（做什么、谁已经在做、盯哪个指标、改善多少和代价）写在对应问题章的末尾；不替业务定目标。

## 取舍

- [ ] 没有交代进度的句子。
- [ ] 没有预防质疑的辩护和澄清句。
- [ ] 限定、待确认、备选数过了一遍：删掉不改变读者决定的；“请业务确认”改成“按 X 测算；若为 Y，结果变为 Z”。
- [ ] 没有跑题的旁枝；本文答不了、又不影响决策的问题不提。
- [ ] 没有不支撑行动的推演、口径修正过程和方法出处（数据来源保留）。
- [ ] 结论段没有中间过程的数。
- [ ] 不确定的写“分辨不出”“不能归因”，不写“无效”“无关”。
- [ ] 假设值、用户定的事、外部输入三者分清并标来源。

## 一句话

- [ ] 文档章节标题是名词短语（项目另有约定的除外）；汇报片页标题是结论句，一行写完。
- [ ] 每张图的标题是第一眼能在图上验证的结论；汇报片每张图上方有一句要点。
- [ ] 一章一件事，一张图一句话。

## 读者

- [ ] 读者最可能问的三个问题都有答案；“需要关注”只收要别人配合做的事和会改变决策的风险，其余问题写进会前追问清单或给用户的回复。
- [ ] 抽象的规则后面紧跟具体例子；难懂的概念先人话、再公式、再例子。
- [ ] 用词逐句查过：没有口语、绝对化副词和自造的概念；图里的字没有重叠、没被截断，单位写全。

## 分析类

- [ ] 关键数有绝对值、相对值和一个能说明好坏的对标。
- [ ] 瀑布图对过账：首尾是两期的值，中间加起来等于差额，同一单位，分不到类的单列。
- [ ] 原因判断分了强弱，全篇一个标准；定为主要原因的有过程证据（案例或对照组）。
- [ ] 诊断专题里每条建议都能追到一个已证实的原因；查过的原因（含排除的）汇成附录一。
