# 顺序叙事改成答案先行：两个实例

> `ethan-pyramid-storyline` 的参考文件。两个实例都是虚构的，数字也是编的，只用来演示常见的改法。

## 实例一：月付价格要不要调回去（方案类）

**改前（按分析顺序讲）**：项目背景 → 数据说明 → 调价时间线 → 续费率对比（第 1 步）→ 退款申请对比（第 2 步）→ 收入对比（第 3 步）→ 三个方案比较（第 4 步）→ 建议

读者要读到最后一章才知道建议是什么，前面都在展示分析路径。

**改后**：

1. 结论与建议（建议 / 预期效果 / 收入影响 / 需要关注的两件事）
2. 月付续费率的变化（先讲已经发生的事）
3. 维持新价和调回原价的对比（效果和收入放在同一张表里）
4. 测算依据（价格、到期量、续费率三项假设各自的来源）
5. 风险与配合事项

删掉的东西：方法上的分歧（“三种预测下每月少收 5.2 万到 7.6 万”改成“约 6 万”）、事实段末尾的论证尾巴（“这说明必须调回去”）、衍生指标（“每个订阅少收 0.38 元，为原价的 2.1%”改成“每个订阅约少收 0.4 元”）。

## 实例二：新手引导改版的效果评估（评估类）

**改前（v1）**：一、背景（缘起 + 问题 + 结论 + 建议）→ 二、改版的使用情况（统计口径 → 使用量 → 结论）→ 三、激活率变化（对比口径 → 前后对比 → 结论）→ 四、是否全量（成本 → 建议）

问题：每章先讲口径再讲结果，结论在章末；第四章先讲成本再讲建议。

**改后（v2）**：

- 一、结论与建议：情境和变化各一句 → 两条结论（各一句加粗 + 一句支撑）→ 建议
- 二、改版的使用规模：首段结论 → 每周使用量 → 使用者构成 → 统计口径（章末）
- 三、两组的激活率对比：首段结论 → 实验期对比 → 分新老设备看 → 对比口径（章末）
- 四、全量上线的条件：首段建议 → 成本 → 落地要点
- 口径说明

一句话的改法：**把每章的“怎么判”从章首挪到章末，把“判出来什么”提到章首。**
