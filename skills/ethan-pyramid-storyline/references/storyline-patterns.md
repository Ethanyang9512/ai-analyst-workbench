# 叙事方法和出处

> `ethan-pyramid-storyline` 的参考文件。只收能直接用的规则，每条给一个例子（虚构）。出处都是公开出版物或公开方法，链接请自行检索原书原文。

## 一、金字塔原理（Barbara Minto，《金字塔原理》）

| 规则 | 例 |
|---|---|
| 结论在顶，理由居中，证据在底。思考可以自下而上，表达要自上而下 | “建议先恢复月付原价两周观察” → 三条理由 → 每条挂数据 |
| 上层是下层的概括；同一层同类；同一层有序（时间、结构或程度） | 三条“原因”里不能混进一条“步骤” |
| 每一句都在读者心里引出“为什么”或“怎么做”，下一层立刻回答 | “续费率掉了 3.8pt” → 读者问为什么 → “60% 是到期的人变了，40% 是涨价” |
| 主结论下面那一层（key line）读完，就知道全文 | 主结论“下降可解释”，下一层＝构成变化 / 月付涨价 / 扣款失败没变 |
| 概括句要有“所以呢”：“有三个原因”是空话，“三个原因都指向同一次调价”才是结论 | — |

## 二、SCQA 开场

- S 情境：读者已经认同的事实；C 冲突：什么变了；Q 问题：由此要回答什么；A 答案。
- 开场里不放新信息；不设单独的“背景”章（它和正文的抽象层级对不上）。
- 给赶时间的读者用“先答案”的变体：A 在前，S、C 各一句跟在后面。本工作台的报告第一章就是这种写法。

例：S“续费率一直在 81% 上下”；C“W6 起掉到 77%”；Q“掉在哪类订阅”；A“60% 来自首次续费变多，40% 来自月付涨价”。

## 三、先写故事线，再做页面

- **先写纯文本故事线**：每个顶层论点＝将来的页标题，下面挂支撑事实。和用户对齐的是这份文本，改故事线不用重做页面。
- **“幽灵稿”**：每页只有标题、一个图的草图和“缺什么数据”，完成度很低就拿去对齐方向。本工作台的对应动作是：动笔前先给用户看“每章一句结论”的骨架。
- **页标题写结论**：完整的句子、说结论不说过程、带数字；标题里出现“和”“以及”多半该拆成两页。
- **一页一个信息**：整页只回答“为什么我该相信这个标题”。
- **只读标题能讲通**：文档的章节标题是名词短语时，这个测试用各章首句来做。

## 四、书面文档和汇报片

叙事文档对作者难、对读者容易：读者按自己的节奏读，第 2 页的疑问在第 4 页得到回答；会前静读、边读边记问题。汇报片适合现场讲、一眼看图。本工作台的做法：飞书文档是可以静读的叙事文档，汇报片从文档派生（`ethan-slide-deck`），两者共用一套故事线和图。

## 五、本技能吸收的五个检查

| 检查 | 问什么 |
|---|---|
| 结论埋在后面吗 | 第一屏有没有答案 |
| 所以呢 | 每一段、每一页答得出“所以呢”吗 |
| 理由审计 | 同一层的理由是否同类、有序、互不重叠 |
| 只读标题或首句 | 连起来是不是完整的故事 |
| 出处约定 | 每个数能不能指回一张表或一个口径 |
