# 可复核的分析交付

一个结论算交付完成，标准只有一个：**复核的人能从源表一路走到图上那根柱子，每一步都能自己重做一遍。**“结论看起来对”不够。下面三样东西缺一样，结论再漂亮也不算交付：

- 跑不出来的中间步骤（“用脚本处理了一下”不算交代）；
- 只有数值、看不到公式的 Excel（看不到公式就只能选择相信）；
- 只有图、没有数据的图表（图是结论的表达，不是证据）。

本技能适用于所有参与分析的一方：取数助手、分析助手，以及以后接手的任何人或智能体。和某一方的默认习惯冲突时，以本技能为准。

## 最常被违反的五条

1. **SQL 聚合过头。** 唯一的判据：*想换一个维度看，能不能不改 SQL 就做到？* 能，就合适；不能，就把聚合退回 Excel 或分析脚本。最常见的违反是直接 `GROUP BY` 出三列结果，因为最省事。
2. **口径只写在代码里。** 代码说明怎么算，注释说明为什么这么算，后者才是被审的对象。没有 header 注释的 SQL 视为没交付。
3. **覆盖了旧版本。** 口径变了、字段增删了，就进新版本号；旧版挪进 `sql/_archive/`；`sql/_CHANGELOG.md` 只追加，不改不删。
4. **计算结果手填成数值。** 原始观测保持原样；计算一律用公式；假设和可调驱动集中在参数区。不要把算出来的数或隐含假设填成像原始数据的数字。
5. **假设不标来源。** 每个参数标明来自：数据 / 用户拍板 / 分析方假设。三者不能混。

确实无法用 SQL 复现的环节，直说，并给出别的核查办法（见“本技能管不到的”）。不要造一个跑不通的 SQL 充数。

## 一、SQL

**组织**

- 一个分析步骤一个文件，不合成一个大文件；命名 `sql/S<两位步骤号>_<用途>_v<版本>.sql`。
- 步骤号按分析链路的先后编，不按创建时间。
- 版本从 v1 起；口径或字段变了进版本，纯排版不进。
- 每次新增或修改，在 `sql/_CHANGELOG.md` 追加一行：日期、文件、版本、改了什么、为什么、谁改的。

**每个文件开头一段 header 注释**，模板在本技能的 `assets/sql-header-template.sql`。要写清：这一步取什么、给谁用；输出一行是什么；输入表各是什么；时间口径（每个日期字段指什么日子、哪个时区）；过滤和剔除了什么、为什么；输出字段和单位；聚合到什么程度；对应 Excel 的哪个子表。

**不过度聚合**。例：要看“分渠道 × 分方案的续费率”。

| 做法 | 判定 |
|---|---|
| SQL 直接 `GROUP BY 渠道, 方案` 输出三列 | 过头：想改成分周看，就得回去改 SQL |
| SQL 输出订阅周期级明细（含渠道、方案、到期日、结果），Excel 用 SUMIFS 汇总 | 合适：换任何维度都在 Excel 里改 |

SQL 负责取数、关联和口径过滤；汇总和计算尽量留给 Excel 公式或分析脚本。

## 二、Excel

**固定的子表**

| 子表 | 放什么 |
|---|---|
| `README` | 用途、子表清单、口径说明、对应哪些 SQL、版本和更新日期 |
| `参数` | 全部假设和可调参数，集中一处、黄底；每个参数注明来源 |
| `RAW_xx` | SQL 直出的明细，一个 SQL 一个 RAW 页，字段名和 SQL 一致，不做任何加工 |
| `计算_xx` | 用公式引用 RAW 和参数，逐步计算；每列表头写明这一步在算什么 |
| `图表_xx` | 图的数据区（引用计算页）和 Excel 原生图 |
| `作图方法` | 每张图怎么重画 |

**公式**要简单、可读、可改：SUMIFS、SUMPRODUCT、INDEX/MATCH 这一类。不用难懂的数组公式和超长嵌套。

**颜色**：黄底＝可以改的参数；灰底＝SQL 直出，别改；白底＝公式结果，改了会被覆盖；红字＝待拍板或存疑。

## 三、图

| 用途 | 形态 |
|---|---|
| 文档里的静态图 | 出图脚本生成的图片，保留数据和脚本 |
| 汇报片里的数据图 | 默认可编辑：PowerPoint 原生图表，或团队认可的其他可编辑路线 |
| 复核用的图 | Excel 原生图，放在交付 Excel 的 `图表_xx` 页 |

几种图用同一份数据，都能追溯到 SQL。

**“作图方法”页**对每张图写五样：数据区（例 `计算_续费!A3:C11`）、图表类型、系列设置（哪列作分类、哪列作值）、格式（配色色值、柱宽、网格线、标签位置、坐标轴）、对应报告里的第几张图。标准是：照着这一页操作，能得到一张和报告里那张数据一致的 Excel 图，样式可以略有差别。

## 四、本技能管不到的

划清边界，免得为了凑形式造假：

- **外部公开信息**（财报、行业报告、媒体报道、第三方测算）跑不出 SQL。它们的可复核性靠：来源链接 + 可信度分级（A 一手披露 / B 主流媒体具名信源 / C 第三方测算）+ 核实状态（已核原文 / 只看了摘要 / 未核），逐条标注。
- **定性判断和业务推理**：标成“推导”“解读”，和事实分开写，不伪装成有数据支撑。

## 五、交付前自检

**SQL**
- [ ] 每一步都有独立可跑的文件，header 完整，口径和过滤原因写清了
- [ ] 改动进了新版本，`_CHANGELOG.md` 有记录
- [ ] 按“不过度聚合”的判据自测过

**Excel**
- [ ] RAW 页是 SQL 直出，没有人工加工
- [ ] 随便点一个计算格都能看到公式；计算区没有用手填数替代公式
- [ ] 参数页标色，每个参数有来源；README 写全了子表和 SQL 的对应

**图**
- [ ] 每张图有对应的数据区；“作图方法”写到照着能重画；图上的数和计算页一致

**全局**
- [ ] 每个假设标了来源；无法用 SQL 复现的环节已说明，并给了别的核查办法
