# 审数据包，写需求包

协作的样子：用户请**取数助手**写 SQL、跑数，取数助手交回一个数据包；分析助手审包、写审核报告；有实质问题就出下一轮需求包，经用户转交；没有就结束，进入分析。写和审分开：写 SQL 的一方不审自己的结果。

只授权审核时，给发现和修改要求；用户明确要求直接修包或改代码时，在指定范围内改完并验证。

## 一、收包：先解包，再体检

```bash
python3 <本技能目录>/scripts/extract_package.py <包.zip> <新的审核目录>
python3 <本技能目录>/scripts/pkgcheck.py <本轮审核目录> --prev <上一轮审核目录> \
        [--report <取数助手的说明.txt>] [--ignore <审核方自己的文件>]
```

- **解包**：放进新目录，原包保留，不覆盖上一轮；拒绝越界路径、软链和重名文件。中文 zip 文件名先按 UTF-8 读，旧编码才试 GBK。
- **体检**（只用标准库、不联网、不改包）查四样：
  - 和上一轮比每个文件的指纹（MD5）、行数、Excel 各表行数；说明里写了“已修复”，数据文件却没变，报**严重**；
  - Excel 公式缓存为空的格数（提醒）；
  - 明文手机号、身份证号、邮箱、口令（输出时打码）；
  - CSV 日期列的首尾日期、缺哪几天、是不是整周（只报事实）。
- **退出码**：3＝有“说改了没重跑”；1＝有别的新的严重问题；0＝没有。上一轮就有、文件也没变的问题照样列出，但不计入退出码。
- 审核方自己写进轮次目录的文件（`审核报告_v*`、`复核记录_*`）自动排除；其他的用 `--ignore` 排除。
- 体检报 0 条不等于可以少审。它不查 Markdown 和 Excel 里同名指标是否一致、表连接有没有扇出，这两样要人工核。

一轮一个目录（`round1/`、`round2/`……），不覆盖上一轮，复核要靠版本对比。每轮结束更新项目状态（结论、已修 / 未修、下一步）。

## 二、六个攻击点

1. **数据层验真。** 说明里改了，不等于数据重跑了。每轮都核数据文件的指纹、行数和几个关键值。报告里写“已核对”，就写出核的是哪个文件、哪个值；包里没有那个文件就写“缺失”。**数据文件指纹没变时，不接受“已修复”的说法。**
2. **SQL 的表和过滤条件。** 用的是不是过期的临时表？日期过滤漏没漏？两个典型信号：数量正好是时间窗的整数倍（28 天对 7 天约 4 倍）；算出的数恰好等于以前已经纠正过的错误值。
3. **取值和连接时悄悄丢行。** 同一个对象有两种写法（全称和简称）时，按第一行取值可能拿到很小的那一行，再被阈值过滤掉，整个对象从结果里消失。核对分组数和总量能不能对回总表。
4. **建议是不是以前否决过的方案。** 下结论前先读项目 `_status.md` 的历史，避免重开一条已经验证无效的路。
5. **正确性要有能被证伪的判据**，不是“看着合理”。例：反事实测算的结果不能好于基准期；物理上做不到的部分，可挽回的量必须为 0；分项加总必须等于总数。
6. **叙事一致。** 两个结论并存却互相矛盾（“主要是用户主动取消”和“主要是扣款失败”），要求收敛成一条链路。

先做能检验关键判断的最小独立复算，再决定要不要下一轮。非阻塞的小问题在本机处理，不拉取数助手全量重做。

## 三、审核报告

文件名 `审核报告_v<N>_<日期>.md`，放在本轮目录。模板：本技能的 `assets/审核报告.md`。三块：

1. **复核表**（第 2 轮起必有）：上一轮每条 → 已修 / 未修 / 部分修，附**证据**（指纹、行数、重算值），不接受“说明里说改了”。
2. **本轮发现**：P1 错误必须修 / P2 缺陷应该修 / P3 建议由用户定；每条写清在什么输入下会出什么错，附重算的正确值。
3. **发布就绪度**：哪几部分可以用，哪几部分等重跑。

结论级的发现（会推翻整篇结论的）先单独告诉用户，不压到报告末尾。审核耗时长，分阶段说进度。

## 四、需求包和取数字段清单

**需求包**（模板 `assets/需求包.md`）要自足：取数助手只看这一个文件就能干活。

- 同一时段的多个小需求合成一个文件；
- 包含用户上次明确说“已转给取数助手”之后的全部未转内容，不确定转没转就按没转处理；
- 已验证正确的部分写进“保留不动的”，不无故要求重跑；
- 回复最后固定一行：`给取数助手：<文件名，或“无”>。还需要取数助手做的事：无 / 有（已写在包里）。`

**取数字段清单**（模板 `assets/取数字段清单.md`）是新专题的第一份需求：明细表一行是什么；字段（后面可能要切的维度一次要齐）；时间窗；去重键；核对用的合计值；个人信息不出库；时间字段统一时区。清单存成项目里的一个文件，路径写进 `_status.md`。以后的需求包随包附上清单原文，正文只写变化。回包先按清单核对字段、行数、合计和去重键，再做业务审核。
