# 正式汇报片

正式汇报沿用**你自己的母版**（公司或团队的 .pptx 模板），用 python-pptx 出片；当前项目已认可的结构和视觉优先。文字、表格和数据图默认要可编辑。

本技能只带规则和自检程序（`scripts/check_deck.py`，测试在 `tests/`），不带母版和建片库。母版、版式索引、常用元素的函数，请按你的模板自己写一个小库，或直接用 python-pptx。

## 环境

```bash
${AAW_PY:-python3} 你的建片脚本.py
${AAW_PY:-python3} <本技能目录>/scripts/check_deck.py 产出.pptx
```

`$AAW_PY` 指一个装了 python-pptx、matplotlib、pandas、openpyxl 的解释器；没设就用装好依赖的 `python3`。

## 流程

**在飞书里出片时先起进度卡**（用分析助手运行时）：第一个工具调用是 `python3 "$AAW_CARD_PY" start <本轮chatId> "<片名>" "定骨架|出图|组片|自检|发文件"`；每个阶段的第一条命令开头先翻卡（`python3 "$AAW_CARD_PY" step 2 "正在出图" >/dev/null; …`），发完文件 `done`。翻卡要写进命令里，靠“记得”就会漏，用户看到的就是一张停在第 1 步的卡。渲染和自检都在前台跑，不放后台然后结束回合：回合一结束，后台进程会被收掉，产物发不出去。

1. **故事线**用 `pyramid-storyline`；用户明确要咨询式高管摘要时再加 `executive-summary`。一轮只定一次骨架。完整文档转成片子时保留内容，不自动缩成摘要版。
2. **一页一个结论，页标题就是那句结论**，带数字，一行写完（不超过 28 个汉字）；分模块时写成“模块 | 结论”。
3. **建片脚本和产出都放在项目目录里**，输出路径写成项目内的相对路径，不按脚本所在位置推算。
4. **片上的数全部从数据源现算**，脚本里不写死数字；每个数都能指回底表的哪一列。
5. **跑程序自检**：
   ```bash
   ${AAW_PY:-python3} <本技能目录>/scripts/check_deck.py 产出.pptx --terms 自造词1,自造词2 --dump \
       [--footer-top <页脚色条上沿 cm>] [--officecli --preview _preview.png]
   ```
   七项：文件完整、色值合法（另提示图表里配色表以外的颜色）、元素越界、文字块重叠、术语黑名单、文字溢出（按字宽估算：python-pptx 写的自动缩放框在 PowerPoint 里不会自己撑高）、图表数据标签位置（标签位置和图表类型不匹配时 PowerPoint 会拒绝打开文件，而 python-pptx 和 schema 校验都查不出）。退出码 0 才算过。`--palette` 改配色表，默认就是 `report-writing` 出图规范里的六色加白色。
6. **程序查不出的三件事自己补**：
   - 写一段校验脚本，把片上每个数对回数据源，瀑布图首尾要自洽；
   - 把 `--dump` 打出的全片文字逐句读一遍：比喻、口语、过度断言只有人能看出来；
   - 跑一轮 `critical-review`。
7. **出片后逐页看图**：转成 PDF 再按页转 PNG，逐张打开看。文字重叠、标签压线只有看图才发现。导出的 PDF 还可以跑 `report-writing` 的 `deckcheck.py pdf` 查词被拆在两行、文字出界。

## 七条硬规则

1. **页标题写结论，不写栏目名**：“月付涨价后续费率降了 2.0pt，年付没变” ✅；“续费率概览” ❌。
2. **每张图或表上方一行要点句**（加粗，前面带一个箭头符号），把这张图要证明的结论写死。
3. **图表不要网格线，数值轴不显示刻度**，数字靠数据标签。配色和文档一致：主角黑 `#1A1A1A`、对照浅灰 `#B9B9BC`、背景更浅灰 `#DDE0E4`、目标和强调红 `#C0392B`；绿 `#2E9E5B`、红 `#D64545` 只表达好坏。品牌色只给页面色块和封面，不给图上色。
4. **口径定义一律进脚注** `[1] [2]`（小号斜体灰字），正文不解释口径。
5. **数字全部从数据源现算**，不写死。
6. **大白话**：团队内部的自造词换成人话；必须保留的专业词第一次出现时加括号解释；读者熟悉的行业术语（ARPU、留存率）保留。
7. **交付前必须跑自检**，不是看一眼就发。

每张图都带来源：图下脚注最后一条写数据来源，例 `[3] 数据来源：W1–W8 到期订阅明细（YYYY-MM-DD 版）`。

## 选图的一条业务规则

**瀑布图只能画能累加的分解**（起点 → 各因素 → 终点）。每次只动一个参数的敏感性分析，各情景互斥，要用横向条形图。瀑布的形状本身就在说“逐步累加”，用错就是把互不相干的情景讲成能叠加：这是业务错误，不是审美问题。

其余选图看 `pyramid-storyline/references/chart-chooser.md`。折线按角色上色：focus（黑，一图最多一个）、compare（浅灰）、context（更浅灰）、target（红虚线）、accent（红）。

## 出图：先保证可编辑

适配的数据图用 PowerPoint 原生图表或形状（装了 think-cell 的可以用 think-cell，但不能把原生图表叫作 think-cell）。只有用户接受静态图、明确要图片、或这种图型做不成可编辑对象时，才用 matplotlib 出 PNG，画法照 `report-writing/references/chart-style-guide.md`。汇报片的 PNG 和文档的图只差两处：图里不画主副标题（页标题和要点句已经说了），画布比例跟着页面上的图区走，按厘米开画布、插进去 1:1 不缩放。每张 PNG 先自己打开看一遍再放进片子。

## 一页高管摘要的骨架（只在确需摘要时参考；数字均为虚构）

| 页 | 作用 | 标题写法 |
|---|---|---|
| 1 | 执行摘要：结论、代价、要拍的板 | “下降可解释：60% 是首次续费变多，40% 是涨价；建议 W10 复看” |
| 2 | 情境和变化 | “续费率 W6 起从 80.8% 降到 77.0%” |
| 3 | 拆解 | “构成变化拉低 2.3pt，月付涨价拉低 1.5pt” |
| 4 | 代价和把握 | “若维持新价，每月续费收入仍多约 4 万（区间 2 万–6 万）” |
| 5 | 风险和没验证的假设 | “关键假设是首年优惠到期潮在 W10 前结束，尚未核实” |
| 6 | 要谁在什么时候决定什么 | “W9 前确认是否调整首年优惠的续费提醒” |

这是示例，不是页数上限。按问题分组、信息完整性和可读性定页数；同一判断的图、表和案例可以合页。

## 最容易踩的坑

- Python 的 `%` 格式化串里写 `+50%`、`31%~42%`，要写成 `%%`，否则报错。
- 瀑布的颜色语义：正数记“变差”色（红）、负数记“改善”色（绿）。讲“收入增长”时红色会误导，要在要点句里点明视角。
- 表格行数超过一页放得下的，拆页或聚合，别缩字号硬塞。
- 页标题两行会把正文往下挤，定了位置的元素会被压住；一律一行。
- 色值写错（不是 6 位十六进制）会悄悄产出 PowerPoint 打不开的文件，`check_deck.py` 会拦；自己写的小库里也加一道校验。
- 字体：西文用你的品牌字体（没有就用母版默认），中文用微软雅黑或苹方，分别指定。
