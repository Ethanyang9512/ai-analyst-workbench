# 设计取舍与替代方案

这一篇回答“为什么不是别的做法”。每个关键设计写四样：选了什么、放弃了什么、代价、什么时候该换。读完你应该能判断哪些值得照搬、哪些在你的环境里不划算。

**结论：** 这套工作台的取舍有一条主线：**宁可多花一点时间和用量，也要让“数字对不对、规矩有没有被遵守”不依赖模型的自觉。**所以检查尽量交给程序和另一个审查者，规矩尽量放进代码和钩子。代价是每次交付多几分钟、多一些用量；交付物越小、越不正式，这些设计越不划算。

## 一览

| 设计 | 选了 | 放弃了 | 主要代价 | 什么时候该换 |
|---|---|---|---|---|
| 验收 | 另一个只读子代理冷读和核数 | 作者自查；只靠程序 | 每轮多几分钟和一次子代理的用量 | 内部草稿、一次性答疑 |
| 验收凭证 | 按文件内容指纹记一行 | git 提交记录；人工签字 | 改一个字节就要重新验收 | 文件很多、改动很碎的场景 |
| 取数协作 | 需求包经用户转交 | 助手直接调用取数一方 | 用户要转两次手 | 取数一方是可信的只读接口 |
| 长期要求 | 钩子在每条消息后补提醒、在命令前拦截 | 全写进系统提示 | 钩子要维护、要测试 | 不接飞书、只在终端用 |
| 检查 | 能写成程序的写成程序 | 让模型检查 | 程序只认写法，会漏、会误报 | 判断类、表达类的问题 |
| 沉淀 | 同类纠正第二次才写进约定页 | 每次纠正都写成规矩 | 第一次纠正后可能再错一次 | 口径类决定：第一次就写 |
| 改技能 | 先考试再上线 | 想到就改 | 要攒考卷、搭考场 | 没有成对稿时，只能先小步改、看手改比例 |
| 隔离 | 一个群一个工作区 | 一个大工作区装所有项目 | 开新项目要配设置、记忆 | 项目很少、彼此紧密相关 |

## 验收交给另一个子代理，而不是作者自查

**选了**：两位只读的验收员。读者验收员只拿到成品和术语表，看不到项目里的其他文件；图表数字验收员回数据源用代码复算。

**放弃了**：

- **作者自查**：写的一方带着全部背景，读自己的稿子会自动补上没写的东西。“术语第一次出现没解释”这类问题，作者几乎看不出来。
- **只靠程序**：程序查得出禁用词、文字重叠、指纹没变，查不出“这张图没表达标题的结论”“这一步跳了”。

**代价**：每轮多几分钟、多一次子代理的用量。分档验收（小改只看改动页）就是为了压这个代价。

**什么时候不值得**：内部草稿、一次性的答疑、只改了标点。工作台用 `ACCEPT_SKIP='理由'` 留痕放行。

**一个误判的例子**：读者验收员不知道“宽限期”是业务通用说法，把它报成“看不懂的词”。这类建议级的发现不返工，只有“必须改”才返工，避免验收员把作者带偏。

## 验收凭证用文件指纹，而不是 git 或人工签字

**选了**：`accept_record.py` 按文件内容的 SHA-256 记一行；验收门在发送前查这个指纹。

**放弃了**：

- **git 提交记录**：工作区里的交付物（PDF、PPT、Excel）多半不进 git；就算进了，“提交过”也不等于“验收过”。
- **人工签字或口头确认**：没法在发送命令执行前自动查。

**代价**：文件改一个字节，记录就失效，要重新验收。这正是想要的效果：防止“验收完又改了一处”的稿子带着旧的验收结论发出去。

**什么时候该换**：文件很多、改动很碎时，可以按目录或按版本号记，但要接受“记录对应的不一定是发出去的那一份”。

**一个误拦的例子**：用 `for` 循环一次发多个文件时，验收门推算不出每个文件的路径，按“没有记录”处理。所以约定发送命令里直接写出文件名（见 [10 踩坑清单](10-踩坑清单.md)）。

## 需求包经用户转交，而不是助手直接调用取数一方

**选了**：分析助手写一份自足的需求包，回复末行固定写“给取数助手：<文件名>”，由用户转交；数据包也由用户转回来。

**放弃了**：让分析助手直接调用取数的一方（同一台电脑上的另一个会话、一个能连库的工具）。

**为什么同一台电脑上也这样做**：

- **写审分离**：写 SQL 的一方不审自己的结果。直接调用时，很容易变成“分析助手指挥取数助手改到对得上为止”，审的一方变成了写的一方。
- **少拿数据**：分析助手只拿到分析用得到的字段，个人信息不出库。直接连库，权限就收不住了。
- **用户知情**：每一次取数、每一轮改动都经过用户的手，用户知道数据从哪来、改了几轮。

**代价**：用户要转两次手；需求包必须写得自足，不然转过去还要来回问。

**什么时候该换**：取数一方是一个只读、限定字段、带审计的接口时，可以让助手直接调用，但审核报告照写。

## 长期要求放进钩子，而不是全写进系统提示

**选了**：`remind.py` 在每条用户消息后面补几句长期要求（先复述理解、只做被要求的、用大白话，说“要汇报”时提醒全稿验收）；`guard.py`、`gate.py` 在命令执行前拦截。

**放弃了**：把这些全写进系统提示或 `CLAUDE.md`。

**为什么**：系统提示越写越长，越往后的要求越容易被忽略；而且提示只能“劝”，挡不住已经发出的命令。钩子贴在每条消息后面，位置最近；拦截类的要求写成程序，模型被材料里夹带的指令骗了，命令也执行不了。

**代价**：钩子要写测试、要做历史命令回放、出错可能影响所有会话。所以入口包了一层“任何异常都放行”，只有钩子主动输出拦截才算拦。

**什么时候该换**：不接飞书、只在终端用时，钩子默认不生效（只在桥启动的会话里生效），把 `workflow.md` 里和飞书无关的部分合进项目 `CLAUDE.md` 就够了。

**一个误拦的例子**：护栏要拦“启停桥进程”，早期版本把路径里恰好带着桥程序名的普通命令也拦了。历史命令回放才发现，见 [05 规矩怎么演进](05-规矩怎么演进.md)。

## 能写成程序的写成程序，而不是让模型检查

**选了**：禁用词（`style_lint.py`）、内部痕迹（`trace_scan.py`）、出图重叠（`figcheck.py`）、幻灯片用词和改动范围（`deckcheck.py`）、数据包没重跑（`pkgcheck.py`）都由程序查，几秒钟出结果，同样的输入结果相同。

**放弃了**：让模型“检查一遍”。模型检查会累、会漏，而且同一份稿子两次结果不同。

**代价**：程序只认写法。换个说法就漏（所以台账支持省略号和“X 代表一个数”这类变体写法）；合法的长词会被误报（所以有放行名单）。程序报“没问题”不等于没问题，**程序报错或没查成也不能写成通过**（`deckcheck.py` 用退出码 2 表示“没查成”）。

**什么时候该换**：判断类、表达类的问题（图有没有表达结论、论证有没有跳步）只能交给验收员和用户。

## 同类纠正第二次才写进约定页

**选了**：用户的纠正当轮记下（台账、项目状态），同类第二次出现才写进项目 `_CONVENTIONS.md`；用户说明适用于所有项目、或从改动推断的规则在两份文档里都出现过，才升进全局。

**放弃了**：每次纠正都立刻写成规矩。

**为什么**：用户的一次改动常常是这份稿子的特殊情况（为了版面、为了这位读者）。每次都写成规矩，规则库很快膨胀、互相矛盾，见 [05 规矩怎么演进](05-规矩怎么演进.md)。

**代价**：第一次纠正之后，同样的错可能再出现一次。

**例外**：口径类的决定（分母用什么、周怎么切）第一次就写进约定页，因为错一次的代价是整份结论作废。

## 先考试再上线，而不是想到就改技能

**选了**：改技能前后用同一份考卷、同一套打分脚本各考一次（[07 先考试再上线](07-先考试再上线.md)）；最终看用户接下来几份真实交付的手改比例有没有降。

**放弃了**：觉得有道理就改。

**为什么**：规则改了以后，模型可能在别处变差（例如自查时改了更多本来没问题的句子），不量就看不到。

**代价**：要攒成对稿当考卷、在 macOS 上搭沙盒考场，每次考试有正常的模型用量。

**什么时候该换**：没有成对稿时，只能先小步改、每轮最多改三条，盯住手改比例；SQL、口径、Excel 里的数有已知答案，直接写成回归测试更好。

## 一个群一个工作区

**选了**：每个飞书群对应一个项目目录，现状、约定、验收记录都在里面；换群就换目录。

**放弃了**：一个大工作区装所有项目。

**为什么**：项目之间的文件、约定和上下文不串；护栏也能据此判断“发到别的群”。

**代价**：新目录要配设置（缺了网络代理会静默失败）、记忆要链接到共享位置。`runtime/bin/newproject` 把这些做成了一条命令。

**什么时候该换**：项目很少、彼此紧密相关时，一个工作区加子目录更省事。

## 每层关卡大概花多少

| 关卡 | 时间量级 | 用量 | 跳过它的风险 |
|---|---|---|---|
| 程序检查 | 几秒 | 几乎没有 | 禁用词、重叠、没重跑这类低级错误直接到用户手上 |
| 两位验收员（小改档） | 一两分钟 | 两次子代理，只看改动页 | 改动页里的新错误 |
| 两位验收员（全稿） | 几分钟 | 两次子代理，通读 | 一路小改积累出没人通读过的稿子 |
| 对抗式审查 | 几分钟到十几分钟 | 视对象而定，复杂时多个子代理 | 假设和口径上的错误 |
| 先考试再上线 | 一次考试几十分钟 | 一次完整的模型运行 | 规则改了反而变差，却不知道 |

这些是量级，不是测量值，随稿子大小和模型版本变化很大。
