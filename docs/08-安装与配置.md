# 安装与配置

这一篇讲怎么把工作台装到你的电脑上：只用技能的最小安装、接飞书的完整安装、桥需要提供什么、代理和模型放在哪、Windows 上要注意什么，以及常见问题。

**结论：** 最小安装只要复制两个目录、合并一份 CLAUDE.md，几分钟就能用；接飞书要再设环境变量、给工作区写设置、接一个桥。整套工作台在一台有权限的电脑（Mac 或 Windows）上完成：分析助手和桥都跑在这台电脑上；取数助手可以是同一台电脑上的另一个智能体会话，也可以是同事。

## 环境要求

**必需：** Claude Code CLI（已登录）、Python 3.9 或更新版本。

**可选：**

| 工具 | 用来做什么 | 什么时候需要 |
|---|---|---|
| lark-cli | 发飞书消息、读写飞书文档 | 接飞书时 |
| 一个飞书桥 | 把群消息转给本机的 `claude -p` | 接飞书时 |
| python-pptx、matplotlib、PyMuPDF、openpyxl、pandas | PPT 检查、出图和出图自检、查导出的 PDF、读写 Excel | 做文档、PPT、审数据包时 |
| OfficeCLI | PPT 结构校验和转图预览 | 做 PPT 时（可选） |
| PuLP、HiGHS、OR-Tools | 优化问题的求解器 | 用 optimization-modeling 时 |

建议给检查程序单独建一个 Python 环境，并用环境变量 `AAW_PY` 指向它：

```bash
python3 -m venv ~/.venvs/aaw
~/.venvs/aaw/bin/pip install -r requirements-dev.txt     # 检查程序和优化示例要的全部可选依赖
export AAW_PY=~/.venvs/aaw/bin/python
```

注意 PyMuPDF 是 AGPL 许可，只在 `deckcheck.py pdf` 里用到；不需要查 PDF 可以不装。

## 最小安装：只用技能

适合只在终端里用 Claude Code、不接飞书的情况。

**第一步，复制技能和验收员。**

macOS / Linux（推荐用安装脚本：同名的旧技能会先挪到备份目录，不直接覆盖；加 `--dry-run` 只看不装）：

```bash
bash tools/install.sh --dry-run
bash tools/install.sh
```

也可以手工复制：

```bash
mkdir -p ~/.claude/skills ~/.claude/agents
cp -R skills/*/ ~/.claude/skills/
cp agents/*.md ~/.claude/agents/
```

Windows（PowerShell）：

```powershell
New-Item -ItemType Directory -Force "$HOME\.claude\skills", "$HOME\.claude\agents" | Out-Null
Copy-Item -Recurse -Force skills\* "$HOME\.claude\skills\"
Copy-Item -Force agents\*.md "$HOME\.claude\agents\"
```

技能里的配套程序按技能目录的相对路径运行，复制时保留目录结构。手工复制时，`~/.claude/skills/` 里已有同名技能会被覆盖，先备份。每个技能只引用自己目录里的文件，只装其中几个也能用。

**第二步，合并工作协议。** 把 [templates/global-CLAUDE.md](../templates/global-CLAUDE.md) 里你认可的部分合进 `~/.claude/CLAUDE.md`。已有这个文件的话，不要整份覆盖。

**第三步，开一个项目。** 新建一个项目文件夹，把 [templates/workspace/](../templates/workspace/) 里的 `_status.md`、`_CONVENTIONS.md`、`_glossary.md` 复制进去，在这个文件夹里启动 `claude`，试一句“按 analysis-brief 帮我开一个新分析：……”。想先看看填好的样子，打开 [examples/续费率下滑归因/](../examples/续费率下滑归因/)。

## 完整安装：接飞书

### 第一步：设环境变量

复制 [runtime/config.example.env](../runtime/config.example.env) 为 `runtime/config.env`（这个文件名已在 `.gitignore` 里），按每行的说明改。钩子、工具和模型进程都从桥继承这些变量，所以要让**桥进程启动前**加载它（例如在桥的启动脚本里写下面这行）；在终端里跑测试和体检之前，也先加载一次：

```bash
set -a; . runtime/config.env; set +a
```

主要变量（和桥有关的几项见样例文件末尾）：

| 变量 | 含义 | 默认值 |
|---|---|---|
| `AAW_RUNTIME` | runtime 目录（钩子、工具、workflow.md）。分析助手的命令里会用到它，接飞书时要设成本机仓库 `runtime/` 的绝对路径；填错了 `workspace_settings.py` 会报错退出 | 脚本自己不设时用所在的 `runtime/` 目录 |
| `AAW_WS_BASE` | 各项目工作区的总目录（一个群一个子目录，`default/` 给私聊用） | `~/aaw-workspaces` |
| `AAW_PROFILE` | 桥的身份名；钩子只在 `LARK_CHANNEL_PROFILE` 等于它时生效 | `aaw` |
| `AAW_HOOK_STATE` | 钩子状态目录（日志、`GATE_ENFORCE`、存活记号） | `runtime/hooks` |
| `AAW_CARD_PY` | 进度卡脚本 | `$AAW_RUNTIME/bin/card.py` |
| `AAW_CLAUDE_JSON` | 每轮提醒钩子读额度缓存的文件 | `~/.claude.json` |
| `AAW_KB` | 知识库根目录 | `~/aaw-kb` |
| `AAW_PY` | 装了 python-pptx、matplotlib、PyMuPDF 的解释器 | `python3` |
| `PAIRSNAP_ROOT` | 成对稿存放处 | `~/aaw-pairs` |
| `AAW_EXAM_ROOT` | 考场目录 | `/tmp/aaw-exam` |
| `AAW_SHARED_MEMORY` | 想让各项目共用一份记忆时，填共享记忆目录 | 不设（不共用） |

### 第二步：建默认工作区，写设置

```bash
mkdir -p "$AAW_WS_BASE/default"
cp runtime/manual/CLAUDE.md "$AAW_WS_BASE/default/CLAUDE.md"
python3 runtime/workspace_settings.py apply --path "$AAW_WS_BASE/default" --kind base
python3 runtime/workspace_settings.py check          # 只检查，不写
```

[runtime/manual/CLAUDE.md](../runtime/manual/CLAUDE.md) 是飞书场景的共享手册，各项目工作区都导入它。`workspace_settings.py` 只增改自己管的几个键，其余键（模型、代理等）原样保留，可以重复执行。它管：

- 关掉后台运行（`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`）；
- 推理强度（`effortLevel`）；
- 登记钩子（只登记 `runtime/hooks/` 里实际存在的脚本）；
- 项目工作区额外关掉用不上的插件、隐藏无关的技能；
- 禁止用改文件的工具改护栏、规则和设置（`permissions.deny`）。

可调的字段在 [runtime/workspace_settings.json](../runtime/workspace_settings.json)：`effort`（推理强度，默认 `high`）、`disabled_plugins`（项目工作区要关掉的插件）、`hide_skills` 和 `hide_skill_prefixes`（项目工作区要隐藏的技能名和名字前缀）。改完运行 `apply --all` 写进全部工作区。

### 第三步：开第一个项目

```bash
runtime/bin/newproject <目录名> "<项目中文名>" <chatId>
```

它会建好项目工作区、复制默认工作区的设置并补上项目设置、生成项目 `CLAUDE.md`（导入共享手册）、链接 `bin/` 小脚本、建 `_status.md` 骨架；设了 `AAW_SHARED_MEMORY` 时，再把项目的记忆链接到共享记忆。目录名只用英文、数字和 `-`。

建完还要让桥把这个群指向新工作区。以 ACKNOWLEDGEMENTS 里列的那个桥为例，是由用户本人在群里发一次 `/cd <工作区绝对路径>`（机器人发的不算命令）。建了目录不等于群已经指过去，要发一条消息核实。各目录的作用见 [runtime/工作区目录约定.md](../runtime/工作区目录约定.md)。

### 第四步：接上桥

桥要提供的能力见下一节“桥需要提供的四项能力”。

### 第五步：跑测试和体检

```bash
python3 runtime/hooks/test_guard.py      # 全部测试命令见 CONTRIBUTING.md
bash runtime/doctor.sh
```

`doctor.sh` 只读不写，查五样：Claude CLI 和登录状态；代理端口（设了 `AAW_PROXY_PORT` 才查）；各工作区设置是否一致；钩子是否齐全、是否真的在跑（含全部自测）；桥进程在不在（设了 `AAW_BRIDGE_PGREP` 才查）。结果分“严重”和“关注”两级。

### 第六步：决定验收门的模式

- 默认是**提醒模式**：没有验收记录也能发，只给提醒。
- 想改成**强制模式**：在钩子状态目录（`AAW_HOOK_STATE`，默认 `runtime/hooks/`）下建一个空文件 `GATE_ENFORCE`。
- 想临时关掉全部钩子：在 `runtime/hooks/` 下建一个空文件 `DISABLED`；删掉就恢复。

## 桥需要提供的四项能力

本仓库不含桥。任何能把飞书消息转给本机 `claude -p` 的桥，只要提供下面四项就能接上：

| # | 能力 | 不提供会怎样 |
|---|---|---|
| 1 | 把 `runtime/workflow.md` 追加进每个新会话的系统提示（例如用 `--append-system-prompt-file`） | 执行流程没注入，分析助手按默认习惯做事 |
| 2 | 新会话的第一轮运行 `python3 runtime/status_preview.py <工作区>`，把输出附在提示里 | 每次 `/new` 都要用户重讲一遍背景 |
| 3 | 在消息里放一段 `bridge_context`，至少带本轮群号（形如 `"chatId": "oc_…"`） | 进度卡起不来；“发到别的群”这条护栏失效 |
| 4 | 启动 `claude -p` 时带环境变量 `LARK_CHANNEL_PROFILE`，值等于你的 `AAW_PROFILE`，并把 `AAW_*` 变量传下去 | 钩子全部不生效 |

可选的第五项是**阶段检查**：在批量写入和发送之前，分析助手可以问桥“这一轮还该不该继续”。用户在分析助手干活时又发了新消息，桥回答“让位”（yield），分析助手就把现状写进 `_status.md`、结束这一轮，桥接着处理新消息。没有它也能用，只是用户中途改主意时，要等这一轮做完才看得到。

另外，每一轮都要以一段文字收尾：桥通常只把最后一段文字当作正式回复发到群里。

可替换的地方（桥的程序名、密钥文件名、发消息的命令、群号格式）和三个常见的坑，见 [runtime/接入飞书桥.md](../runtime/接入飞书桥.md)。可以直接用的开源桥见 [ACKNOWLEDGEMENTS.md](../ACKNOWLEDGEMENTS.md)。

## 代理和模型

- **放在工作区的 `.claude/settings.json` 里。** 如果你的网络需要代理，代理相关的环境变量放在这份设置的 `env` 里；模型也可以在这里固定。新目录没有这份设置，请求会失败（常见是 403），而且不报错。`newproject` 会从默认工作区复制一份，默认工作区也没有时用 [runtime/settings.example.json](../runtime/settings.example.json)。
- **推理强度写在工作区设置的 `effortLevel`**，由 `workspace_settings.json` 的 `effort` 统一维护。
- **改了 workflow.md 要发 `/new` 才生效**：续接旧会话时，Claude Code 沿用开会话时那份系统提示。

## Windows 说明

- **钩子入口是 sh 脚本**（`runtime/hooks/run-hook.sh`）：装 Git for Windows（自带 Git Bash）或用 WSL。`runtime/bin/` 下的小脚本同理。
- **Python 命令可能叫 `python`** 而不是 `python3`，测试命令照你的环境改。
- **考场的 `sandbox-exec` 只有 macOS 有**：Windows 上用单独的系统账户或容器隔离，见 [exam/README.md](../exam/README.md)。
- **`pairsnap.py` 用到 `fcntl`（文件锁），Windows 原生 Python 没有**：存成对稿请在 WSL 里跑。其他检查程序在 Windows 上可以直接用。
- 环境变量里的路径用正斜杠，或者注意转义反斜杠。

## 常见问题

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 钩子没生效 | `LARK_CHANNEL_PROFILE` 和 `AAW_PROFILE` 不一致；入口没有执行权限；工作区设置里没登记钩子 | 对一下两个变量；`chmod +x runtime/hooks/run-hook.sh`；重跑 `workspace_settings.py apply`；看 `doctor.sh` 报的各钩子最近触发时间 |
| 验收门说推算不出文件位置 | 发送命令里的路径用了变量、通配符或命令替换 | 先 `cd` 到文件所在目录，`--file` 后直接写文件名 |
| 改了 workflow.md 不生效 | 旧会话沿用开会话时的系统提示 | 在群里发 `/new` |
| 新项目一直 403 或没反应 | 工作区缺 `.claude/settings.json` | 用 `newproject` 建，或从默认工作区复制一份设置 |
| 进度卡报 AMBIGUOUS | 几个群同时有进行中的卡，没指定是哪张 | 命令前加 `CARD_CHAT=<chatId>` |
| 子代理还没跑完，回复就提前发出 | 没关后台运行 | 确认工作区设置里有 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` |
| 分析助手跑的命令报 `zsh: ==== not found` | macOS 默认的 zsh 会把 `=` 开头的词当成命令路径展开，`echo =====` 这类分隔线就会出错 | 分隔线写成 `echo '-----'`（共享手册里已经写了这条） |
