# 踩坑清单

这一篇把散在各处的坑集中到一张张表里：现象、原因、做法、对应的文件。很多坑不报错，只是悄悄干不了活，最费时间。细则仍在原处，这里只做索引。

**结论：** 坑大多出在三个接缝上：**Claude Code 和桥之间**（会话、后台任务、最后一段文字）、**钩子和命令之间**（钩子在命令之前跑、会并行、会变目录）、**数据和口径之间**（时区、滞后、构成变化）。前两类在工作台里已经写成了设置、钩子和测试；第三类写进了技能的口径坑和指标卡。

## 一、Claude Code 与桥

| 现象 | 原因 | 做法 | 对应文件 |
|---|---|---|---|
| 新项目一直 403 或没反应，也不报错 | 网络代理、模型这类设置写在工作区 `.claude/settings.json`，只对这个目录生效；新目录没有这份设置 | 用 `newproject` 开项目，它会复制默认工作区的设置 | [runtime/bin/newproject](../runtime/bin/newproject)、[08](08-安装与配置.md) |
| 新项目像失忆了 | Claude Code 按工作区的绝对路径存记忆，新目录等于一份空记忆 | 想共用就设 `AAW_SHARED_MEMORY`，开项目时把记忆链接过去 | [02](02-运行逻辑.md)、[runtime/工作区目录约定.md](../runtime/工作区目录约定.md) |
| 子代理还没跑完，回复就发出去了；或者长任务做到一半没了 | 后台运行时会产生多个结果事件，桥把“还在处理”当成最终答复；回合结束时桥会结束整棵进程树 | 工作区设置里写 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`，命令和子代理都在前台跑完 | [runtime/workspace_settings.py](../runtime/workspace_settings.py) |
| 群里什么回复都没收到 | 这一轮只有工具调用，没有一段文字收尾；桥只把最后一段文字当正式回复 | 每一轮都以一段文字收尾，等待或部分完成时也写明现状 | [runtime/workflow.md](../runtime/workflow.md) |
| 改了 `workflow.md` 不生效 | 续接旧会话时，沿用开会话时那份系统提示 | 各群发 `/new` | [08](08-安装与配置.md) |
| 助手不停地回复自己 | 用用户身份（`--as user`）往机器人监听的群发了消息，桥当成新消息又交给助手 | 发消息一律 `--as bot`；护栏专门拦这一条 | [runtime/hooks/guard.py](../runtime/hooks/guard.py) |
| 建了项目目录，群里说话还在旧目录干活 | 建目录不等于群已经指过去 | 用户本人在群里发一次切换目录的命令（机器人发的不算），再发一条消息核实 | [08](08-安装与配置.md) |
| 命令报 `zsh: ==== not found` | macOS 默认的 zsh 把 `=` 开头的词当成命令路径展开 | 分隔线写成 `echo '-----'` | [runtime/manual/CLAUDE.md](../runtime/manual/CLAUDE.md) |

## 二、钩子

| 现象 | 原因 | 做法 | 对应文件 |
|---|---|---|---|
| 同一条命令里生成文件再发送，验收门说找不到记录 | 钩子在命令**执行之前**运行，这时文件和记录都还不存在 | 生成文件、写验收记录、发送分成三条命令 | [04](04-质量关.md)、[runtime/hooks/gate.py](../runtime/hooks/gate.py) |
| 验收门说推算不出文件位置 | 发送命令里的路径用了变量、通配符或命令替换 | 先 `cd` 到文件所在目录，`--file` 后直接写文件名 | [08](08-安装与配置.md) |
| 钩子算出来的路径不对 | 钩子输入里的当前目录会跟着上一条命令里的 `cd` 变 | 钩子里按命令推算路径，不假定当前目录不变 | [runtime/hooks/gate.py](../runtime/hooks/gate.py) |
| 进度卡状态偶尔被写坏 | 同一条回复里并行的几个工具调用，钩子也并行在跑 | 共享状态加锁（`O_EXCL` 建锁文件）或用带进程号的临时文件，替换用原子操作 | [runtime/hooks/progress.py](../runtime/hooks/progress.py)、[runtime/bin/card.py](../runtime/bin/card.py) |
| 缺一个钩子脚本，所有命令都被拦 | 钩子非零退出被当成拦截 | 入口包一层：脚本不存在、找不到 Python、任何异常都放行，只有钩子主动输出拦截 JSON 才算拦 | [runtime/hooks/run-hook.sh](../runtime/hooks/run-hook.sh) |
| 这一轮的最终答复不见了 | Stop 钩子做了拦截，顶掉了最终答复 | Stop 钩子只做安静的收尾，不输出、不拦截 | [runtime/hooks/progress_stop.py](../runtime/hooks/progress_stop.py) |
| 很长的命令偶尔没被拦 | 几十 KB 的命令逐条跑正则太慢，超时就成了放行 | 先做廉价预检：一个相关关键词都没有就直接放行 | [runtime/hooks/guard.py](../runtime/hooks/guard.py) |
| 改了护栏，正常命令被误拦 | 新正则命中了没想到的写法（路径里恰好带桥的名字、`for` 循环发文件） | 上线前用历史命令回放一遍 | [runtime/tools/replay_history.py](../runtime/tools/replay_history.py) |
| 设置里禁止读某个文件，考生还是读到了答案 | Claude Code 设置里的读取禁令只管内置的读文件工具，管不住 Bash 里的 `cat`、`python` | 考场用操作系统级的沙盒（macOS 的 `sandbox-exec`），并先跑自检 | [exam/README.md](../exam/README.md) |

## 三、数据和口径

| 现象 | 原因 | 做法 | 对应文件 |
|---|---|---|---|
| 两张表按天对不上，周末那天差得最多 | 一张表记 UTC、一张记本地时间，零点前后的记录落到了另一天、甚至另一周 | 取数时统一时区，写进字段清单和 SQL 注释 | [templates/fetch-request/取数字段清单.md](../templates/fetch-request/取数字段清单.md) |
| 最近一周的比率总是偏低 | 指标有滞后或宽限期，数据还没落定就取了 | 字段清单里写明“哪天之后取数才完整” | [examples/续费率下滑归因/](../examples/续费率下滑归因/) |
| 比率掉了，每一类拆开看却都没怎么变 | 构成变化：分母里各类的比例变了 | 先拆“构成变化”和“各类比率变化”，两项相加等于总变化 | [skills/pyramid-storyline](../skills/pyramid-storyline/)「指标波动的讲法」 |
| 汇总后某个对象整个消失 | 同一个对象有两种写法，按第一行取值拿到了很小的那行，被阈值过滤掉 | 连接前统一写法；核对分组数和总量能对回总表 | [skills/data-package-review](../skills/data-package-review/) |
| 说明里写“已修复”，数却没变 | 数据没有重跑 | 每轮比文件指纹；指纹没变不接受“已修复” | `pkgcheck.py`，真实输出见 [示例 outputs/04](../examples/续费率下滑归因/outputs/04_pkgcheck_说改了没重跑.txt) |
| 程序写出的 Excel，别人打开公式格是空的 | 程序写的公式没有缓存值，只有在 Excel 里打开重算后才有 | 体检报“公式缓存为空”；交付前在 Excel 里打开保存一次 | `pkgcheck.py` |
| 中文 zip 解出来文件名是乱码 | 打包工具用的编码不同 | 先按 UTF-8 标记读，只有旧编码才试 GBK；不要对所有文件名强制换码 | `extract_package.py` |

## 四、出图、出片和飞书文档

| 现象 | 原因 | 做法 | 对应文件 |
|---|---|---|---|
| 平滑折线画出了不可能的值（排名 0、负比率） | 普通样条插值会过冲 | 点少用单调三次插值（PCHIP），点多用移动平均 | [chart-style-guide](../skills/report-writing/references/chart-style-guide.md)、`chart_template.py` |
| 换了字体后中文变成方框 | 字体没装或缓存没更新 | 用中文字体回落链；装完新字体重建缓存；出图后打开看一遍 | `chart_template.py` |
| PowerPoint 里文字压到下面的元素 | python-pptx 写的自动缩放框，在 PowerPoint 里不会自己撑高 | `check_deck.py` 按字宽估算真实高度并报溢出 | [skills/slide-deck](../skills/slide-deck/) |
| PowerPoint 拒绝打开文件，python-pptx 和 schema 校验都没报错 | 图表数据标签的位置和图表类型不匹配；或色值不是 6 位十六进制 | `check_deck.py` 查这两项 | `check_deck.py` |
| Python 报 `unsupported format character` | `%` 格式化串里写了 `+50%` | 写成 `%%` | [skills/slide-deck](../skills/slide-deck/) |
| 重推飞书文档正文后，图片全没了 | 覆盖重推不会保留之前插入的图片 | 只改图时替换单个块；改了正文就重新插图并逐张归位 | [feishu-ops](../skills/report-writing/references/feishu-ops.md) |
| 插图后有一张掉在文末 | 插图只能先插到文末再移动，移动可能静默失败 | 批量插图后按章节列一遍图片分布 | [feishu-ops](../skills/report-writing/references/feishu-ops.md) |
| 插出了重复的图 | 命令输出里进度信息在 JSON 前面，整段解析失败后又重试了一次 | 用正则取需要的字段；解析失败先回读确认，不重试 | [feishu-ops](../skills/report-writing/references/feishu-ops.md) |
| 以为单元格底色没生效 | 回读默认只取简版，不带样式 | 查样式时取完整信息 | [feishu-ops](../skills/report-writing/references/feishu-ops.md) |
| 程序自动填 think-cell 图，颜色不对、文件要修复 | think-cell 的系列颜色跟着演示文稿主题走；往图表 XML 里插入新元素会让 PowerPoint 提示修复；它还会重排系列 | 生成后改每个系列的填充色；改 XML 只替换已有元素；按数值而不是按位置认系列（本仓库不带相关脚本） | — |

## 五、检查程序本身

| 现象 | 原因 | 做法 | 对应文件 |
|---|---|---|---|
| 台账里记了禁用词，程序还是没拦住 | 一行用斜杠连写两个词被当成一个整词；或者用户删掉的说法换了个字又出现 | 斜杠两边分别匹配；省略号表示中间可以夹几个字 | `style_lint.py`、[style-lexicon](../skills/report-writing/references/style-lexicon.md) |
| 纠正记在台账的项目小节里，程序不查 | 程序只读「一、硬禁」表 | 只适用本项目的写进项目约定页的 json 块，由 `deckcheck.py` 查 | [06](06-知识库怎么组织.md) |
| 存成对稿时 `--root` 不认 | 旧版只接受写在子命令前面 | 现在写在 `save` 前后都行 | `pairsnap.py` |
| 程序报错了，却被写成“检查通过” | 没查成和查过没问题是两回事 | `deckcheck.py` 用退出码 2 表示没查成；验收时没查成的项要写明 | [04](04-质量关.md) |
