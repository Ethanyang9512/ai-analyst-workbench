# Brief：新手引导改版的实验评估（v1，2026-04-01）

> 本例数字均为虚构。按 `analysis-brief` 的五要素写；**判定规则在看数据之前定好**，用户 04-01 确认。

| 要素 | 内容 |
|---|---|
| 背景 | 示例 App 把新手引导从 5 步改成 3 步，做了两周 A/B 实验（新用户随机分到对照组和改版组，各约 1.2 万人）。产品负责人要决定改版要不要全量上线。 |
| 要回答的问题 | 改版有没有提高新用户的 7 日激活率（7 天内完成第一次导出）；能不能据此决定全量。 |
| 交付形式 | 一份一页的实验读数（结论、区间、决定、下一步），附口径说明。 |
| 限制 | 只看事先登记的主指标；分组（新老设备）只描述，不拿来下结论；不估算收入。 |
| 检查点 | ①判定规则（下表）先给用户确认；②数据回来后先跑 `analysis/readout.py`，再写结论。 |

## 事先登记的判定规则（04-01 用户确认，看数据之前定）

| 项 | 规定 |
|---|---|
| 主指标 | 7 日激活率：新用户 7 天内完成第一次导出的比例，改版组减对照组，单位 pt |
| 区间 | 95%，正态近似 |
| 可忽略带 | ±0.5pt：差别在这个范围内，对业务没有意义 |
| 采用线 | +1.0pt：低于这个提升，不值得承担改版的维护成本 |
| 四档决定 | 区间下界 ≥ +1.0pt → 采用；区间上界 < 0 → 拒绝；区间整个落在 ±0.5pt 里 → 维持现状；其余 → 分辨不出，继续收集 |

## 开题前攻一遍设计

| 攻击点 | 结论 | 处理 |
|---|---|---|
| 两周够不够？ | 按现在的流量，两周后区间半宽约 ±1.2pt，比可忽略带宽一倍多，很可能“分辨不出” | 事先告诉用户这个可能，结论写法也事先定好 |
| 看完数据再挑分组行不行？ | 挑出来的分组差异多半是偶然 | 分组只描述，不作结论 |
| 激活要等 7 天，最后几天进来的人算不算？ | 不满 7 天的人激活率偏低 | 只算实验结束前满 7 天的新用户 |
