# 示例项目：新手引导改版评估

和主例 [续费率下滑归因](../续费率下滑归因/) 互补：主例是**解释一个指标为什么变了**（拆解、找原因），这一例是**评估一个改动有没有用**，而且结论是最难写好的那一种——“分辨不出”。

## 先跑一下

```bash
cd examples/新手引导改版评估
python3 analysis/readout.py
```

输出（真实运行结果）：

```
对照组 12,000 人，7 日激活率 31.0%；改版组 12,000 人，31.4%
差 +0.4pt，95% 区间 -0.8pt 到 +1.6pt（可忽略带 ±0.5pt，采用线 +1.0pt）
判定：分辨不出，继续收集
区间半宽缩到 ±0.5pt 需要每组约 65,970 人；按每组每周 6,000 人，还要约 9 周
分组描述（事先没登记，不作结论）：
  新设备：31.5% → 31.3%，差 -0.2pt，区间 -1.6pt 到 +1.2pt
  老设备：30.0% → 31.6%，差 +1.6pt，区间 -0.4pt 到 +3.6pt
```

## 这个例子演示什么

| 做法 | 在哪 | 为什么 |
|---|---|---|
| 判定规则在看数据之前定好，并让用户确认 | [brief.md](brief.md) | 看完数据再定阈值，阈值会不自觉地往结果靠 |
| 没测出变化只有四种写法：采用、拒绝、维持现状、分辨不出 | [analysis/readout.py](analysis/readout.py) 的 `decide()` | “不显著”不等于“没效果”；写“改版无效”是把分辨不出说成了否定 |
| 结论里给区间，不只给一个差值 | [报告骨架.md](报告骨架.md) 第二章 | +0.4pt 本身说明不了什么，区间才说明把握有多大 |
| 告诉读者还要多久才能下结论 | 报告骨架第三章 | “分辨不出”之后，读者最想知道的是下一步怎么办 |
| 看起来很诱人的分组差异，只描述不下结论 | 报告骨架第四章 | 老设备 +1.6pt 是看完数据才挑出来的，区间也跨过了 0 |

用到的技能：`ethan-analysis-brief`（五要素和事先登记）、`ethan-pyramid-storyline` 的「分析类汇报的四条」和 `references/readout-rules.md`（实验读数的结构、决策四档）、`ethan-report-writing`（写正文）、`ethan-critical-review`（交付前攻一遍）。
