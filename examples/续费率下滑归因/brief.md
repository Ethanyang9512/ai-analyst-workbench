# Brief：续费率下降原因（v1，2026-03-10）

> 本例数字均为虚构。按 `ethan-analysis-brief` 的五要素写；用户 03-10 确认。

| 要素 | 内容 |
|---|---|
| 背景 | 示例 App（一款虚构的订阅制修图工具）的周续费率 W1–W5 稳定在 80.6%–80.8%，W6 起掉到 77% 左右，W7、W8 没有回升。增长负责人要在下周一的周会上说明原因。 |
| 要回答的问题 | 续费率为什么从 W6 起下降约 4pt；是用户主动取消变多，还是扣款失败变多；集中在哪类订阅。 |
| 交付形式 | 一份 Markdown 报告（周会前发群里），结论先行，3–5 张图；不做 PPT。 |
| 限制 | 只分析续费，不分析新购（用户 03-11）；读者是增长和产品负责人，正文不写 SQL 和字段名；周按周一到周日。 |
| 检查点 | ①报告骨架（每章一句结论）先给用户看；②数据包审核通过后再出图；③周会前一天发第一版。 |

## 开题前先攻一遍分析设计（子代理只攻设计，不碰数据）

| 攻击点 | 结论 | 处理 |
|---|---|---|
| 分母用当周到期订阅数还是当周活跃订阅数？ | 用活跃订阅数会把还没到期、根本不需要续费的订阅也算进来，续费率被稀释，而且到期量一变就会假波动 | 定为当周到期订阅数，写进 `_CONVENTIONS.md` 第 3 条 |
| W6 到期的订阅和 W5 是同一批人吗？ | 不是。W6 起有一大批去年首年优惠买的年付订阅第一次到期，这类订阅的续费率本来就低；整体下降可能只是“到期的人变了” | 取数时一次要齐“方案”“首次/多次续费”两个字段，先拆构成变化 |
| “W6 月付涨价”能不能直接当原因？ | 同期不等于原因。年付没有涨价，可以当对照：只有月付掉、年付不掉，才支持涨价这个解释 | 报告里分开写“同期发生”和“数据显示” |
| W8 的数完整吗？ | 续费在到期后 3 天宽限期内完成的都算；W8 周日到期的订阅，要到 W9 周三才知道结果 | W8 数据在 W9 周四之后取，写进 `_CONVENTIONS.md` 第 4 条 |

## 不做的

- 不评价涨价该不该做、不建议新的定价（不替业务定目标）。
- 不估算收入损失。
